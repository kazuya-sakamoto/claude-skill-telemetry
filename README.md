# claude-skill-telemetry

Claude Code の**スキルが、どれだけ使われ、いくらかかっているかを実測する**プラグイン。

スキルのコードは 1 行も変えない。install して設定ファイルを 1 つ置けば、あとはセッションを開くたびに実行記録が溜まっていく。

```
.claude/skills/
├── handoff/
│   ├── SKILL.md
│   └── logs/a1b2c3d4.ndjson    ← 12 行 = 12 回使われた
└── grilling/
    └── SKILL.md                 ← logs/ が無い = 一度も使われていない
```

1 行 = 1 実行:

```json
{"run_id":"dfe7be6cee3b","ts":"2026-09-01","skill":"handoff","invoked_by":"slash",
 "turns":2,"duration_s":35,"ctx0":1000,"cost_units":2110,"own_units":1810,
 "model":"claude-opus-5","sub_spawned":1}
```

> **v1 の範囲**: ログをローカルに書くところまで。commit / push / PR の自動化は入っていない。

## 何が嬉しいか

| 知りたいこと                | 引き方                             |
| --------------------- | ------------------------------- |
| どのスキルが実際に使われているか      | `logs/` があるかどうか。ディレクトリを見るだけで分かる |
| どのスキルが高いか             | `cost_units` をスキル別に合計する         |
| 書いたのに使われていないスキルはどれか   | `logs/` が無いディレクトリ               |
| 人が呼んだのか、モデルが自分で選んだのか  | `invoked_by`（`slash` / `auto`）  |
| キャッシュが効いていたか（＝割高だったか） | `ctx0`（起動時の文脈サイズ）               |

効いている性質は 3 つ:

- **スキルと使用実績が同じ場所にある。** 別のダッシュボードを見に行かなくてよく、スキルを消せばログも一緒に消える
- **過去に遡って復元できる。** 計測を意識せずに使っていたセッションも、transcript が残っていれば拾える
- **コミットするかは自分で決める。** ログは `git status` に出てくるだけで、プラグインが勝手に push することはない

**約束: このログを個人の生産性評価に使わない。** 集計はスキル単位で出し、人単位では出さない。ディレクトリ構造自体がそうなるよう作られている（人単位の集計は scatter-gather になり、スキル単位の集計が最も簡単）。**誰のログかは、パスにも中身にも書かれない。** 帰属が必要なときは git のコミット author を引く — つまり名寄せには明示的な行為が要る。

## クイックスタート

```bash
# 1. プラグインを install（既定は user スコープ = 自分の全プロジェクト）
claude plugin marketplace add https://github.com/kazuya-sakamoto/claude-skill-telemetry.git
claude plugin install claude-skill-telemetry@claude-skill-telemetry

# 2. 計測したいリポジトリで opt-in する。必須は since の 1 キーだけ
echo '{ "since": "2026-09-05" }' > .claude/skill-telemetry.json

# 3. 動作確認（<plugin> は install されたプラグインのディレクトリ）
<plugin>/bin/run --status
```

以後は何もしなくてよい。セッションを開くたびに自動で記録される。

- `owner/repo` 形式（`kazuya-sakamoto/claude-skill-telemetry`）でも add できるが、その場合は SSH で clone される。SSH 鍵を GitHub に登録していないなら上の https URL を使う
- チーム全員に配るなら install に `--scope project` を付ける
- install せずに 1 セッションだけ試すなら `claude --plugin-dir /path/to/claude-skill-telemetry`
- 変更を配るときは `plugin.json` の `version` を上げてタグを打つ。`version` は pin として働き、上げない限り `/plugin update` は新しいコードを取らない

## 記録される / されない

| 記録される                             | 記録されない                          |
| --------------------------------- | ------------------------------- |
| スキル名・呼ばれ方（slash/auto）・回数          | **会話本文・プロンプト**                  |
| ターン数・所要秒・トークン内訳・コスト（`cost_units`） | ファイルパス・ブランチ名・リポジトリ名・セッションID     |
| モデル・CLIバージョン・サブエージェント数             | **メールアドレス・氏名**（マシンIDの不可逆ハッシュのみ） |

## どうやって動くか

Claude Code は全会話を transcript（`~/.claude/projects/**/*.jsonl`）として自動保存している。このプラグインは**そこからスキル実行を復元する**。スキル側にフックを仕込む必要も、実行中に何かを書き出す必要もない。

```
あなたの通常のセッション（計測を意識しない）
        │
        ▼  Claude Code が自動保存
~/.claude/projects/<プロジェクトslug>/*.jsonl     ← transcript = リポジトリ外バッファ
        │
        ▼  次のセッション開始時（SessionStart フック、プラグインが自動配線）
   bin/run --sync
        │
        ▼
.claude/skills/<スキル名>/logs/<マシンID先頭8桁>.ndjson
```

**走るのはセッション開始時の一度だけ。** 作業中にファイルが書き換わることはなく、前回までのセッションぶんが次の起動時に静かに追記される。

記録の起点は設定の `since` で、**それより前の実行は取り込まない**。だからログに並ぶ行は常に「since 以降だから、ある」で説明でき、マシンごと・人ごとに開始点がずれない。

## アーキテクチャ

`bin/run` は `dist/cli.js`（依存ゼロの単一バンドル）を叩くだけ。中は 7 段のパイプラインで、**どの段も条件が欠ければ黙って降りる**。

| 段        | すること                                       | 効く設定                                     |
| -------- | ------------------------------------------ | ---------------------------------------- |
| ゲート      | `.claude/skill-telemetry.json` の**存在だけ**見る | （中身は読まない）                                |
| config   | JSON を読んで検証。不正なら停止                         | すべて                                      |
| 身元       | 書き込んでよい書き手か                                | `identity.*`                             |
| skills   | `SKILL.md` を持つディレクトリを列挙（= 記録対象の allowlist） | `skillsDir`                              |
| lock     | `~/.claude/plugins/data/` で排他。負けたら無言で降りる   | （設定なし）                                   |
| scan     | transcript を走査してスキル実行を復元（`requestId` で重複排除）| `timezone` / `tsPrecision` / `excludeCommands` / `since` |
| ledger   | `<skillsDir>/<skill>/<logsSubdir>/<machineID>.ndjson` に merge（`run_id` 冪等） | `skillsDir` / `logsSubdir` |

諦めても安全なのは、transcript が残っている限り次のセッションが同じものを拾い直すから。そのうえで:

- **状態はリポジトリ外**: ロックと最終実行結果は `~/.claude/plugins/data/<plugin>/` に置く。あなたのリポジトリに gitignore の追記は要らない
- **サブディレクトリ起動も拾う**: repo root 以外で開いたセッションも、transcript の `cwd` で判定して取り込む
- **冪等**: 何度走らせても同じ実行は 1 行。実行中に記録された不完全な行は、後の走査で完全な行に置き換わる

## 信頼モデル（install する前に読む）

**このプラグインが持つ権限**:

|     |                                                                                         |
| --- | --------------------------------------------------------------------------------------- |
| 読む  | `~/.claude/projects/**/*.jsonl`（= あなたの会話履歴すべて）／ 設定で machineId を明示しなければ `~/.claude.json` |
| 書く  | `.claude/skills/*/logs/*.ndjson` と `~/.claude/plugins/data/` のロック・状態のみ                  |
| 実行  | **なし。外部コマンドを一切起動しない**                                                                   |
| 送る  | **なし。ネットワーク I/O がゼロ**                                                                   |

**保証しているもの**:

- **外向きの出口が存在しない。** v1 は `git` も `gh` も呼ばず、ネットワークにも触らない。読んで、あなたのリポジトリ内のログファイルに書くだけ
- **本文由来の文字列は一切書かれない。** 会話テキストに触れるのは「先頭300字への正規表現」と「sha256 ハッシュ」の 2 箇所だけで、どちらの結果も本文を復元できない。この不変条件は**テストで固定**されている
- **書かれるものは人間可読。** NDJSON なので目視で全部確認できる
- **テスト用データに実会話が含まれない。** リポジトリに入っている transcript サンプルは手書きの合成データだけ
- `dist/` は CI が `src/` から再ビルドして差分ゼロを検証する

**保証できないもの（正直に）**: OSS ツールを**メンテナの悪意**に対して安全にすることはできない。会話履歴の全読ができる以上、悪意ある版は原理的に作れる。この設計が目指しているのは「**悪意ある変更が diff で一目でわかること**」。実運用では**バージョンを pin し、上流の main を自動追尾しない**ことを勧める。

将来 commit / push / PR を自動化する版では外向きの出口が生まれる。その版では外部コマンド実行を 1 関数に集約し `git` / `gh` のみの argv allowlist にする。

## 設定

`.claude/skill-telemetry.json` の**存在そのものが opt-in スイッチ**。プラグインはまず中身を読まずに存在だけを見て、無ければ即終了する（`existsSync` 1 回）。だから user スコープで install しても、このファイルを置いていないリポジトリでは何もしない。

「このリポジトリを計測する」という判断が**追跡ファイルとしてリポジトリ側にあり、レビューで見える**ことがこの設計の要点で、環境変数やマシン側の設定にするとその可視性が失われる。`since` がその判断の日付になり、git blame で誰がいつ決めたかも追える。

必須は `since` の 1 キーだけで、残りは全部省略できる。既定のまま使うのが普通で、外す理由が説明できるようになってから足せばよい。

| キー                    | 既定                            | 何を決めるか                                          |
| --------------------- | ----------------------------- | ----------------------------------------------- |
| `since` **（必須）**      | なし                            | **この日以降の実行だけを記録する。** 過去に戻せば遡って取り込める（既に書いた行は消えない） |
| `skillsDir`           | `.claude/skills`              | **探索先と書き込み先の両方。** 記録対象のスキルとログの置き場が同時に動く         |
| `logsSubdir`          | `logs`                        | 各スキル配下のどこに置くか                                   |
| `timezone`            | システム TZ                       | `ts` の値と、`since` を比べる暦（チームで日付境界を揃えるときに指定する）     |
| `tsPrecision`         | `day`                         | `ts` を `2026-09-04` にするか `2026-09-04T09:10:00+09:00` にするか（既定が日粒度なのはプライバシー優先） |
| `identity.requireOrg` | `null`                        | この組織でログインしているセッションだけ記録する（v1 は push しないので効果は無い）    |
| `identity.machineId`  | `null`（`~/.claude.json` から取る） | ログのファイル名になる書き手 ID                               |
| `excludeCommands`     | `[]`                          | 記録しないコマンド名（組み込みコマンドは既定で除外済み）                    |
| `sync.level`          | `write`                       | v1 は `write` のみ。他を指定すると起動時に落ちる                  |

未知のキーは無視されるので、補足を足したければ `_comment` を書ける（JSON にコメントが書けないための慣習）。

押さえるべき制約は 2 つ:

- **書き込み先だけを別の場所にすることはできない。** `skillsDir` は相対パスに検証で制限してあり（絶対パスと `..` は拒否）、ログは必ずそのスキルの隣に出る。「`logs/` の有無で使用実績が分かる」という性質を保つための意図的な制約
- **`tsPrecision` の変更は過去に遡らない。** `merge` は `turns` が増えたときしか上書きしないので、後から `second` に変えても既存レコードは `day` のまま。作り直すにはログを消して次のセッションを開く（`since` より前は戻らない）

## どのスキルが記録されるか

ルールは 1 行:

> `SKILL.md` **を持つディレクトリはすべて記録する。コミットされるのは git が追跡しているものだけ。**

つまり **gitignore がそのまま共有境界**になる。

| ケース                                                      | ローカルに貯まる | コミットされる        |
| -------------------------------------------------------- | -------- | -------------- |
| 通常の共有スキル                                                 | ✓        | ✓（あなたがコミットすれば） |
| **gitignore されたスキル**（例: `.claude/skills/_`* のような個人スキル規約） | ✓        | ✗              |
| プラグイン提供スキル・外部スキル                                         | ✗        | ✗              |

個人スキルは**自分だけは見えて、共有事故は構造的に起きない**。プラグイン提供スキル・外部スキルが恒久的に対象外なのは、読み取り専用のインストール先には書けないため。

## 止めたいとき

```bash
touch .claude/no-skill-log        # このリポジトリ×このマシンで記録しない
export SKILL_TELEMETRY_DISABLE=1  # このマシン全体で止める
```

設定ファイルを消せばリポジトリごと opt-out（チーム全体で停止）。

## CLI リファレンス

| コマンド            | 用途                                                    |
| --------------- | ----------------------------------------------------- |
| `--sync`        | フック用。走査して書き込む。無言・exit 0。フック入力（stdin の JSON）が無ければ何もしない |
| （引数なし）          | 手動で 1 回走査（`since` 以降）                                 |
| `--dry-run`     | 書き込まず差分と除外内訳を表示                                       |
| `--report`      | スキル別に集計表示（transcript は読まない）                           |
| `--status`      | 設定・書き込み先・対象スキル・直近のフック結果を表示                            |
| `--repo <path>` | 対象リポジトリを明示（既定は `$CLAUDE_PROJECT_DIR` または cwd）         |

将来 `--nudge`（同期の滞留通知）は、commit / push の自動化を入れる版で追加する。


## トラブルシュート

| 症状                       | 原因と対処                                                                                          |
| ------------------------ | ---------------------------------------------------------------------------------------------- |
| 何も記録されない                 | ① `.claude/skill-telemetry.json` が無い（opt-in していない） ② 設定が読めない（`bin/run --status` を手で叩くと理由が出る） ③ `SKILL.md` が無いディレクトリは対象外 |
| フックが発火しているか分からない         | `bin/run --status` の `last hook:` を見る（`wrote` / `clean` / `skipped:*` が毎回 1 行残る）              |
| **個人スキルのログがコミットされない**    | **正常。** gitignore が共有境界。ローカルでは `--report` に出る                                                  |
| 2 つセッションを開いたら片方が何もしなかった  | **正常。** ロックで直列化しており、負けた側は無言で降りる。次のセッションが拾い直す                                                   |
| スキルをリネームしたら履歴が切れた        | 仕様。ディレクトリが変わるため新旧が別扱いになる                                                                       |
| 過去の実行が記録されない             | ① `since` より前（仕様） ② Claude Code の transcript 保持（`cleanupPeriodDays`、既定 30 日）を超えて、その間このリポジトリでセッションを開かなかった |
| ログが `git status` に出てきて邪魔 | 記録したくないなら `.claude/no-skill-log`、共有したくないだけなら gitignore に追加                                     |

## 開発

```bash
npm install
npm test          # 合成 fixture の golden テストと不変条件テスト
npm run typecheck
npm run build     # dist/cli.js を再生成（コミットする）
```

このリポジトリは**自分自身を計測している**（`.claude/skill-telemetry.json` と `.claude/skills/telemetry-status/`）。プラグインを読み込んでセッションを開くと、自分のスキル実行が `.claude/skills/telemetry-status/logs/` に溜まる。

実 transcript を使った突き合わせ（リファクタの安全網）:

```bash
npm run parity -- /path/to/repo capture   # いまの出力を baseline として凍結
npm run parity -- /path/to/repo verify    # baseline と突き合わせ、差分があれば exit 1
```

実データを読むのでローカル専用。baseline は実スキル名を含むためコミットしない（`tools/parity/out/` は gitignore 済み）。
